
## Software Development Project

### Overview

Working in teams of 3 to 4, you will apply the **Waterfall Software Development Life Cycle (SDLC)** to plan, design, code, test, and maintain a Java application.

You will also critically evaluate Generative AI. You are **NOT** graded on whether you produce a commercial app, or even if the app works perfectly. You are graded on your **SDLC documentation, process rigor, AI analysis, and line-by-line code ownership**.

### Team Roles & Responsibilities

Every group member must adopt primary responsibilities corresponding to the SDLC definitions from class:

- **Project Manager:** Maintains the Software Project Plan, Gantt Chart schedule, Resource List, and shared Google Drive workspace.
- **Systems Analyst:** Leads the Software Scope Document, Feasibility Study, and Step 2 UML Diagrams (IPO, Class, Sequence, Use Case).
- **Lead Programmer & Programmers:** Responsible for Java architecture, internal JavaDoc commenting, and manual post-midterm refactoring.
- **Technical Writer:** Authors the external User Guide/Documentation and maintains the AI Prompt Journal.
- **Tester:** Designs black-box and white-box unit test suites using valid and invalid sample data.

---

## Course AI Policy: The Two-Phase Model

### Phase 1: AI Exploration & Prototyping (Weeks 1 to 10)

- **Policy: PERMISSIVE AI USE.** Generative AI tools (*specifically Gemini, as per board policy*) may be used for ideation, boilerplate code generation, algorithm suggestions, and initial prototyping.
- **Requirement:** Teams must maintain an **AI Prompt & Response Journal** in Google Drive. For every major module generated by AI, record the exact prompt, the output produced, and any identified bugs, logic errors, or bad OOP coupling.

**MIDTERM CHECKPOINT: AI FEASIBILITY AUDIT (Week 10)**

Teams submit their prototype alongside an **AI Feasibility Audit Report** comparing the AI-generated code directly against your Step 1 Problem Analysis constraints (hardware, cost, time, integration, research).

### Phase 2: Human Refactoring & Maintenance (Weeks 11 to 18)

- **Policy: RESTRICTED AI USE.** AI tools are turned off completely.
- **Requirement:** Teams manually refactor, optimize, and debug their Java codebase using core course concepts (Arrays, ArrayLists, Search/Sort, Polymorphism, File I/O). Complete internal JavaDoc comments must be written, and all members must prepare for an individual oral code defense.

## Sprint 1: Requirements & Design Portfolio (Due Week 3)

### Project and Group Selection

Choose groups of 3 or 4. Within each group it's time to brainstorm and pick a project. Be sure to check the project with your teacher before you go off designing it!

Your project should somehow relate/use ALL topics in this course. So that means your project needs to have:

- Multiple classes
- An interface or abstract class
- 2D arrays
- ArrayLists
- A recursive algorithm
- A sorting algorithm
- File Input/Output
- Automated Testing

Your teacher may allow you to exclude one of the above, at their discretion.

### Deliverables:

**1. Software Scope Document (~750 to 1,000 words)**

- **Problem Statement:**
    - *Project Background:* Concise summary of the problem, historical context, and project justification.
    - *Stakeholders & Users:* Itemized list of affected groups/roles and target end users.
    - *Risks & Assumptions:* Outline of potential risks (funding, delays) and timeline/cost assumptions.
- **Vision of Solution:**
    - *Vision Statement:* Reiterate the core purpose and justification for spending time and resources.
    - *List of Features:* Detailed breakdown of both mundane (menus) and major features.
    - *Scope of Phased Release (Optional):* Roadmap identifying initial release features vs. future versions.
    - *Features That Will NOT be Developed:* 3–5 explicit bullet points detailing excluded features and reasons.

**2. Feasibility Study (~900 to 1,200 words)**

- **Problem Definition:** A concise 1-paragraph summary of the proposed application, end users, and inferable purpose.
- **Problem Analysis (Constraints):** Detailed analysis of anticipated constraints, including Hardware requirements, User training time, User age range, Time constraints, Integration (OS and software libraries), and Research requirements.
- **End User Requirements / Recommendations:** Summarized product requirements, including a formatted log of dates and attendees for all requirement-gathering meetings.
- **Software Project Plan:**
    - *Statement of Work (SoW):* Breakdown of parallel tasks assigned to leads, incorporating pseudocode, flowcharts, or storyboards for major features.
    - *Resource List:* Itemized list of required personnel, hardware, software, and rooms.
    - *Work Breakdown / Time Estimates:* Estimated development hours per feature/task with justification.
    - *Project Schedule:* Visual **Gantt Chart** timeline mapping people, tasks, and resources across Weeks 1–18.
    - *Risk Plan:* Matrix identifying potential risks and mitigation strategies.

**3. Design Documents (~3 to 4 pages of diagrams)**

UML diagrams created using visual modeling tools:

- **IPO Diagrams:** Input-Process-Output tables/diagrams for core functions.
- **Class Diagram:** Complete UML class diagram showing attributes, methods, inheritance, and relationships.
- **Sequence Diagram:** Detailed interaction flow between objects for one primary user workflow.

**NOTE: These documents need to be kept up to date! If you make changes that affect UML diagrams, change the diagrams!**

## Sprint 3: Refactoring & Step 4 Testing Report (Due Week 16)

### Deliverables:

- **Refactoring & Code Hygiene Summary (1–2 pages):** Summary of manual optimizations made post-midterm, detailing how AI boilerplate was replaced by hand using algorithms, data structures, and/or File I/O. Includes verification of complete internal JavaDoc documentation for all classes.
- **Automated Unit Test Suites (2–3 pages):** Formatted test tables for Black-Box and White-Box testing containing:
    - Test Case ID & Description
    - Test Type (Black-Box / White-Box / Boundary Case)
    - Sample Input Data (Valid and Invalid test inputs)
    - Expected Output vs. Actual Output
    - Pass / Fail Status
- **User Experience (UX) & Human Testing Log (1–2 pages):** Documented human testing of UI fields, buttons, displays, and menu navigation.
- **Alpha / Beta Testing Summary (1 page):** Feedback analysis from members of the target audience. Get enough external testers to satisfy yourselves that you are as bug free as possible.

### Other Requirements:

During this phase you should also operate as an Alpha or Beta Tester for at least one other group. Each of you will be silently assigned as one of the 3 types of users to emulate while testing. Keep this between you and me. Maybe gaslight your peers as to which one you are? All for funsies!

These users just want to watch the world burn, and they will push every button, find every edge case, combine every key press, jam, jump and twist Link into every corner of Hyrule, just to see what happens. When they find your bugs, and they will, they will find out what they can do to your precious baby. You will not be pleased.

## Sprint 4: Maintenance, User Guide, & Viva Voce (Due Weeks 17–18)

- **External User Guide:** Clear user manual with instructions, navigation guides, and troubleshooting steps.
- **Evaluation Log:** Summary documenting SDLC evaluation questions. Including, but not limited to:
    - *Did the program work well?*
    - *Are there any problem areas? If so, what are they?*
    - *Is the program useful to you or to the target audience, and why?*
    - *Is the program easy to use?*
    - *Do you have any recommendations for improvement to the product?*
- **Individual Viva Voce (10-Minute Group Oral Defense):** Interview with the teacher where every team member individually:
    - Traces assigned code line-by-line to prove absolute code ownership.
    - Explains mapping between Step 2 UML diagrams and implementation.
    - Defends manual refactoring choices made post-midterm to fix AI flaws.

**Did you keep your UML Diagrams up to date? I sure hope so! It'd be a real pain to find out during the interview that you didn't!**
